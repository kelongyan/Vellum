# PdfCraft UI 精修方案（供评审）

> 定位：**精修，不重做**。保持现有三栏骨架、单蓝强调、白纸阅读区、明暗双主题与动画阶梯。
> 本文只做两件事：把"看着不对劲"拆成可验证的事实，再给出有数值、有落点、有验收的改法。
> 依据：`crates/ui-egui/src/` 静态阅读 + `outputs/`、`docs/images/` 现网截图 + 对比度计算。
> 未编译、未运行（按 `Rule/build-and-packaging.md`，等你当次授权）。

---

## 0. 结论先讲

1. **方向没错，缺的是一把尺子。** 色彩（中性 chrome + 单一蓝）、白纸阅读区、克制的描边，都是有品味的选择；问题在于每个控件的身高、圆角、字号、间距都是逐处手调的，同一屏里能出现 8 种按钮尺寸、14 种圆角。
2. **你点名的两处，根因不同。** "输入框偏小"不是统一小，而是**控件族没有规格**（18/26/28/30/32 五种高度混用，其中 5 处在浅色主题下白底无边框，等于隐形）；"选项菜单栏"是**语义同级、视觉不同级**（模式栏里 `Menu` 是描边按钮，`All tools` 等是纯文字）。
3. **最深的一条不显眼但最伤质感：边界太弱。** 浅色边框/面板对比 1.39:1，分隔线 1.22:1；深色选中态 1.33:1，实心蓝按钮上的白字只有 3.33:1。元素之间不是"分得清"，而是"刚好没糊在一起"。

## 1. 先说做对了什么（不动的东西）

| 已成立的决定 | 为什么不改 |
|---|---|
| 中性 chrome + 白色面板 + 白纸页面 | 阅读器该有的克制；Acrobat/Brave 都是这条路 |
| 单一蓝 `#1B63E0` / `#4B8BF5` | 品牌识别已经建立，换色只会显得"换了个壳" |
| 顶栏 38 + 模式栏 48 + 面板 272/330 | 三栏节奏稳定，改宽度会连带动画与测试 |
| 动画阶梯（TAP→LARGE，1e-3 死区） | 已经是这个项目最成熟的一层，本次只复用不新增 |
| Lucide 图标 + Inter/HarmonyOS Sans SC | 图标风格统一，中文回退可用 |

**本次不碰**：信息架构、面板宽度、canvas 渲染、页面交互、图标集、字体、品牌色相。

## 2. 诊断清单

按"用户可感知度 × 修复成本"排序。每条给证据（文件:行）与影响。

### A. 输入与选择控件（你点名的两类）

**A1. 面板搜索框在浅色主题下是隐形的**（P0，bug 级）

- 现象：右侧 Inspector 的 `Search` 只有标签和一个 `×`，输入区看不到；`docs/images/pdfcraft-bookmarks.png` 里深色下却正常。
- 证据：`panels/right.rs:149` 直接用 `egui::TextEdit::singleline`，未走 `widgets::line`。其底色取 `visuals.extreme_bg_color = t.field`（白），描边取 `widgets.inactive.bg_stroke`，而 `theme.rs:465` 把它设成了 `Stroke::NONE`。白底 + 无描边 + 白色面板 = 不可见。
- 同类共 **18 处**裸 `TextEdit`，其中未设高度/边框的至少 5 处会掉到 egui 默认行高（约 18–20px）：`panels/right.rs:149`、`tools/tags_ui.rs:148`、`tools/tags_ui.rs:291`、`dialogs.rs:759`、`dialogs.rs:777`、`custom/home.rs:177`。
- 影响：用户以为"这里没有搜索框"，或误点 `×`。

**A2. 页码与缩放输入框过小、无状态反馈**（P0）

- 证据：`chrome.rs:669` 页码框 `desired_width(34.0)`、字号 12、`Margin(2,4)`；`chrome.rs:601` 缩放框 `desired_width(40.0)`、字号 **11**、`frame(NONE)`、`Margin(2,2)`。
- 实测像素：页码框约 34×24，缩放框约 40×18；三位数页码（100+ 页文档）会挤压，`220%` 这种四字符也几乎顶满。
- 影响：右下角是高频操作区（翻页、缩放），却用着全应用最小的两个输入目标。

**A3. 下拉选择（ComboBox）没有统一宽度**（P1）

- 证据：全库 84 处 `ComboBox`，只有 `dialogs/protect.rs:147/167/182`、`comment_props.rs:250`、`marks_ui.rs:230` 显式给了 `width`；其余宽度随内容浮动，短标签只有 60–80px。
- 影响：对话框里一列下拉框参差不齐，像"没对齐的表单"。

**A4. 输入框高度谱系混乱**（P1）

| 场景 | 当前高度 | 来源 |
|---|---|---|
| 裸 `TextEdit`（面板/标签/提取） | 18–20 | egui 默认 |
| 菜单内控件 | ~26 | `button_padding (10,5)` + 13px 字 |
| 对话框字段 | 30 | `widgets::FIELD_MIN_HEIGHT` |
| 顶栏搜索框（外观） | 32 | `widgets::search_box` |
| 首页命名输入 | 默认（未设） | `custom/home.rs:177` |

四类控件、五种身高，用户读不出"谁是主要输入"。

### B. 尺度与节奏

**B1. 图标按钮 8 档身高**（P1）

- 统计：`icons::button` 调用中 18/20/22/24/26/28/30/32/34 全部出现；主力是 26（27 次）、30（22 次）、32（13 次）、28（13 次）。
- 后果：右侧 rail 一列里同时有 22（清除）、30（翻页）、32（缩放）——肉眼看到的是"参差"，说不出哪里不对。

**B2. 圆角 14 档**（P1）

`CornerRadius::same` 出现 1/2/3/4/5/6/8/10/11/12/14/15/16/17。同一屏内：tab 7、输入框 5、按钮 14/15、卡片 6/10、搜索框 16。

**B3. 字号 14 档**（P1）

7.5/9.5/10.5/11/11.5/12/12.5/13/13.5/14/15/15.5/16/17/18/20/22/28。主字号 13 用了 70 次，但 11–12.5 有 88 次，13.5–18 有 71 次。**相邻档只差 0.5px，读者分辨不出层级，只能靠颜色硬撑。**

**B4. 间距 17 档**（P2）

`add_space` 出现 2/4/5/6/7/8/10/12/14/16/18/20/24/28/30/40/48。4/6/8 占大多数（240 处），其余 99 处是即兴值。

### C. 视觉层级与主题

**C1. 边界对比不足**（P1，质感根因）

| 对象 | 当前 | 对比度 |
|---|---|---|
| 浅色边框 `#DADADE` / 面板 `#FFF` | 1.39:1 | 在 150% 缩放下会糊 |
| 浅色分隔线 `#E8E8EB` / 面板 `#FFF` | 1.22:1 | 几乎只是为了"有个像素" |
| 深色边框 `#3C3C43` / 面板 `#26262A` | 1.38:1 | 同上 |
| 深色分隔线 `#333339` / 面板 `#26262A` | 1.20:1 | 同上 |

**C2. 深色主题选中态几乎不可见**（P0）

`selected #233A63` 对面板 `#26262A` 只有 **1.33:1**，对卡片 `#2E2E33` 只有 **1.19:1**。light 主题同样的 `#E6EEFD` 靠色相还能认出，深色下蓝和灰亮度接近，选中项"消失"。

**C3. 深色主题实心蓝按钮上的白字不达标**（P0）

`#4B8BF5` + 白字 = **3.33:1**（WCAG AA 正文要求 4.5:1）。浅色 `#1B63E0` + 白字 5.37:1 是合格的。所以这是"只有深色模式才有的缺陷"。

**C4. 四种"选中"语言并存**（P1）

| 位置 | 选中表现 |
|---|---|
| 模式栏 tab | semibold + 底部 2px 下划线 |
| 文档 tab | 填成 `chrome` 白，与下方模式栏接上 |
| 右侧 rail | 淡蓝底 + 1px 蓝描边（craft-ui 自带） |
| 列表项/书签 | `accent_soft` 填充 |

四种都合理，但同屏出现时没有"这是一套"的感觉。缺一条规则：**导航用下划线，容器选中用填充，工具开关用描边**。

**C5. 通知条权重过高**（P2）

`canvas/bars.rs` 的 notices 是满宽 `accent_soft` 底色 + 14/7 内边距，紧贴模式栏下方。截图里"文件已修复"那条蓝带的视觉重量超过文档本身。

### D. 结构细节

**D1. 右下导航簇拥挤**（P0–P1）

放大 4× 后看到的实际顺序：页码框 `1`（34×24）→ 总页数 `2`（11px 灰字，**竖排到下一行**）→ `^` → `v` → `220%`（无框，看着像标签）→ 4 个图标（fit/rotate/page display/zoom in/zoom out）→ **断开 6px** → 上方 rail 面板图标。

问题有三：
- 页码和总页数被拆成上下两行，读起来像"第 1 页 / 共 2 行"，语义错位；
- 同一列里 22/28/30/32 四种身高，间距只有 2；
- 面板开关（上方）与视图控制（下方）之间只有 6px 空隙，没有分组线。

**D2. 模式栏语义同级、视觉不同级**（P1）

`Menu` 有 1px 描边 + 6 圆角 + 图标，是一个"按钮"；`All tools / Read / Edit / Convert / E-Sign` 是纯文字 + 下划线。两者都是"打开一组选项"，但描边让 `Menu` 看起来比当前选中的 `All tools` 更重，主次颠倒。

**D3. 首页卡片"框大封面小"**（P1）

`custom/home.rs`：卡片 170×212，封面固定 112×142，居中；间距 22。视觉空缝 = (170−112) + 22 = **80px**。所以截图里卡片显得又小又散，右侧大片空白。
另外页面标题 24（`heading_row`）直接跳到卡片标题 13.5，中间没有 15/17 这一层。

**D4. 顶栏高度三档混用**（P2）

strip 38、tab 30、`Open` 按钮 28、右侧图标 26/28。横向一排，基线不齐。

## 3. 设计规格（Spec）

目标不是"更好看"，是"任何新控件都能查到该多大"。

### 3.1 尺寸标尺（4pt 基准）

```
控件高度   compact 28 · regular 32 · large 36
行高       list 32 · menu 32 · panel-header 36
图标按钮   28（紧凑）· 32（标准）           ← 只保留两档
图标尺寸   14（16 容器）· 16（20 容器）· 18（rail）
内边距     field (11,7) · button (12,6) · panel (14,10)
间距       2（贴合）· 4 · 8 · 12 · 16 · 24 · 32
```

### 3.2 圆角（四档，语义化）

| 档 | 值 | 用途 |
|---|---|---|
| `radius-xs` | 3 | checkbox、缩略图、色块 |
| `radius-sm` | 6 | 输入框、按钮、tab、卡片 |
| `radius-md` | 10 | 对话框、浮层、面板卡片 |
| `radius-pill` | 14 / 999 | 胶囊按钮、搜索框、头像 |

现有 14 档里，5/7/8/11/12/15/16/17 全部并入以上四档。

### 3.3 字号（六档）

| 档 | 值 | 用途 |
|---|---|---|
| caption | 11 | 计数、快捷键、元信息 |
| label | 12 | 表头、字段标签、缩放百分比 |
| body | 13 | 正文、菜单项、按钮 |
| subtitle | 15 | 面板标题、对话框标题 |
| title | 17 | 区块标题 |
| display | 24 | 首页"文稿"这类页面标题 |

13.5/12.5/11.5/10.5/9.5 这些"半档"逐步归并；`section_title` 的 10.5 + 0.6 字距保留（它是唯一有理由的特殊值）。

### 3.4 控件规格

**单行输入框**
```
高度 32 · 内边距 (11,7) · 圆角 6
静止  fill=field, stroke=border_strong
悬停  stroke=text_muted
聚焦  stroke=accent (1.5px) + 外环 accent_soft 2px
错误  stroke=danger
```
> 关键：**输入框永远有描边**。白底白面板的隐形问题从规格层消灭，而不是逐处打补丁。

**下拉选择**
```
高度 32 · 最小宽度 180 · 右侧 chevron 14
菜单行高 32 · 菜单内边距 (12,8) · 圆角 10
```
> 180 是"短标签下拉"的下限，字段宽于 180 时随列宽。

**图标按钮**
```
28 或 32 · 图标 16 · 圆角 6
静止 透明 · 悬停 hover · 按下 pressed（走 tempo::TAP/MICRO，不变）
聚焦 1px accent 环
```

**页码/缩放簇**
```
页码框   48×28，字号 12.5，居中，可键入
页码显示  "3 / 180" 单行，caption 11，text_faint
缩放框   52×28，字号 12.5，右对齐
分组     面板图标（上）— 4px 间隔 + 1px divider — 页面导航（中）— divider — 缩放（下）
```

### 3.5 状态语言（四种，各管一摊）

| 语言 | 表现 | 用在哪 |
|---|---|---|
| 下划线 | 2px accent，随 tab 滑动 | 模式栏、对话框 tab 行 |
| 填充 | `accent_soft` 底 | 列表选中项、菜单 hover |
| 描边 | 1px accent + soft 底 | rail 开关 |
| 环 | 2px accent 外环 | 键盘焦点（所有可聚焦控件） |

**新增一条硬规则：键盘焦点必须可见**。当前只有对话框的 `selection.stroke` 与 `pill_button_marked` 有环，其余控件靠 egui 默认（在自定义绘制的控件上等于没有）。

### 3.6 主题修正（保持色相，只调明度）

| token | 现在 | 改为 | 收益 |
|---|---|---|---|
| `border_strong`（新增） | = border | light `#C4C4CA` / dark `#52525B` | 1.74 / 1.95:1，输入框与卡片边界立得住 |
| `divider` | `#E8E8EB` / `#333339` | 保持（分隔线就该轻） | 不追加视觉噪音 |
| `selected`（dark） | `#233A63` | `#2E4C7D` | 1.33 → 1.76:1 |
| `accent_fill`（新增，dark） | = accent `#4B8BF5` | `#2A66D6` | 白字 3.33 → 5.29:1 |
| `accent`（dark，文字/图标用） | `#4B8BF5` | 不变 | 5.4:1 已达标 |

> `accent_fill` 只用于"实心按钮底"，`accent` 继续用于文字、图标、描边、下划线。浅色主题两者相同，不新增分支。

## 4. 分界面改法

### 4.1 顶栏（tab strip）
- 高度 38 / tab 30 不动。
- `Open` 与右侧图标统一 28；`Home` 28。→ 消除 26/28 混用。
- tab 内图标 15 → 16，与文字基线对齐（现为 `(height-16)/2`，改后逐像素对齐）。

### 4.2 模式栏
- **主推**：`Menu` 去掉描边，改成与 tab 同族的 ghost 文字 + 右侧 `chevron-down` 12；保留左侧 16 图标。理由：它是"一组命令的入口"，不是"一个动作"；去掉框之后，"All tools" 的选中权重自然回到第一。
- 备选（更保守）：保留框，但把描边降到 `divider`，高度 28 → 32，与右侧搜索框齐平。
- tab 字 13.5 → 14（仅 active 用 semibold），下划线维持 2px / `-4.0` 抬升。
- 高度 48 不动（`tests/it/underline.rs` 依赖两行 55px 的测量）。

### 4.3 右侧 rail 与底部簇
- rail 按钮 34（craft-ui 常量）不动；图标 18 不动。
- rail 选中态：`accent_soft` 底 + `accent` 1px 描边 → 只留底 + 2px 左侧指示条（或只留底）。理由：描边+填充在同一条 48px 窄列里显得"重"，且与 tab 的下划线语言冲突。
- 底部簇重排为三段，段间 1px divider：
  1. 页面：`3 / 180` 单行 + 输入框 48×28
  2. 导航：`^` `v` 32（与历史前进/后退同尺寸）
  3. 视图：fit / rotate / page display / zoom± 统一 32，缩放框 52×28
- 页码与总页数合并成一行，解决"1 / 2 竖排"的误读。

### 4.4 侧面板（Inspector / 工具面板）
- 面板头 36：标题 15 semibold，右侧动作 26 → 28。
- 面板内所有 `TextEdit` 收口到 `widgets::line`（32 高 + 描边）。书签搜索框从"隐形"变成可见，这是本方案单点收益最大的一处。
- 列表行 32，缩进层级按 16 递增（现为视觉缩进，深浅不一）。
- `section_title` 10.5/0.6 保留；下方间距 6 → 8。

### 4.5 对话框
- 字段高 30 → 32；按钮 28 → 32（`pill_button`）。
- 表单两列时标签列固定 120，控件列左对齐；单列时最大宽度 420。
- ComboBox 最小宽 180（见 A3）。
- 底部按钮区：主按钮右、次按钮左，间距 8；与内容之间 20（现为 `add_space` 即兴值）。

### 4.6 首页 / 文稿库
- 卡片 170×212 保持，封面 112 → **140×176**（左右各留 15），阴影不变。
- 卡片标题 13.5 → 15，元信息 11.5 → 12；卡片高 212 → 232。
- 标题行："文稿" 24 + 右侧按钮 34；新增一行 15 的副标题（当前文件夹名 / 文档数），填补 24 与 13.5 之间的断层。
- 空状态：说明文字与隐私行之间的 48 间距改为 96/32 两段，让空态重心落在页面中上部而不是散开。
- 网格 gap 22 → 24（与标尺对齐）。

### 4.7 通知条与 toast
- 通知条：满宽 `accent_soft` → `card` 底 + 左侧 3px accent 竖条 + 1px `border_strong`；高度不变。
- toast 与进度条保持现有反色卡片（它们已经对了）。

## 5. 实施计划与优先级

### P0 · 缺陷修复（0.5–1 天，用户当天能感觉到）

| # | 改动 | 落点 | 方式 |
|---|---|---|---|
| 1 | 输入框统一（18 处收口） | `widgets.rs` + 各调用点 | 改 `line()` 默认值，裸 `TextEdit` 换成 `widgets::line` |
| 2 | 输入框描边 | `theme.rs` | 新增 `border_strong`，`begin_dialog` 与面板共用 |
| 3 | 页码/缩放框放大 | `chrome.rs:601/669` | 就地改数值，2 处 |
| 4 | 深色 selected / accent_fill | `theme.rs` 或 `custom/brand.rs` | 改 3 个色值 |
| 5 | 最小点击目标 28 | `widgets::icons::button` 入口 | 一处 clamp，全站生效 |

> P0 全部是"改数值/收口"，无结构变化；`CUSTOM(` 计数不变（`theme.rs` 已有接缝，`chrome.rs` 不新增标记）。

### P1 · 体系化（2–3 天）

| # | 改动 | 风险 |
|---|---|---|
| 6 | 控件三档高度（28/32/36） | 中：`interact_size.y` 是全局值，会连带菜单与面板行高，需逐屏看截图 |
| 7 | 图标按钮 8 档 → 2 档 | 低：机械替换，注意 22 的清除按钮要放到 28 的容器里 |

## 8. 需要你拍板的三件事

1. **模式栏 `Menu` 是否去边框？** 这是全案视觉变化最大的一项（从"按钮"变"文字入口"）。去框更接近 Acrobat、也让 `All tools` 回到主位；保留则更保守。

## 附：落地时的两处修正（2026-10-28）

方案进入实现后被代码证伪的两点，记录在此以免下次再犯：

1. **模式栏 `Menu` 并没有描边。** 截图缩略图里那个"框"是 `panel-left` 图标的方框本身，不是按钮边框；`menu_bar_ui` 用的是默认 `egui::Button`，而 `widgets.inactive.bg_stroke` 早已是 `NONE`。因此"去掉 Menu 描边"这一项**取消**，模式栏只改 tab 字号（13.5 → 14）。
2. **页码与缩放框不能做到 48/52 宽。** 右侧 rail 宽 48、内边距 6，可用内容宽只有 36——现有的 34 和 40 已经是"刚好"和"略微溢出"。所以两框统一为 36（填满可用宽、修掉 40 的溢出），高度与对比度按方案提升，横向尺寸到此为止。要把它们做成 Acrobat 式横向控件条，必须先改 rail 的宽度约束（craft-ui 常量），属于另一轮结构改动。

另：全局 `spacing.interact_size.y = 32` 未采用。`craft-menu` 用 `interact_size.y × 12` 推算菜单宽度，全局 32 会把每个菜单撑到 384 点；控件高度下限改在 `begin_dialog` / `begin_panel` 内生效。

3. **右侧 rail 的选中态也不是"蓝底 + 蓝描边"。** `ChromeStyle::from_visuals` 取的是 `widgets.active.bg_fill`（本主题的 `pressed` 灰）作底，`selection.stroke` 只在键盘焦点时描边。它本来就轻，不需要降重；真正需要的是深色下的底与面板对比（灰 #3E3E45 对 #26262A 约 1.5:1），已随 `pressed` 保持。故该项取消。
